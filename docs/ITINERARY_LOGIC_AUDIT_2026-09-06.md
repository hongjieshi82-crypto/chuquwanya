# 行程逻辑修正与验收记录（2026-09-06）

本轮采用现有 Expo/Express 架构做纵向修复：候选规则 → 本地抽取/服务端筛选 → 行程详情。规则位于 `apps/api/src/itinerary-policy.ts`，前端只引入无网络依赖的纯数据与函数。未更换模型或部署平台。

## 已确认的根因

- 详情页固定抵达 14:20、三站 14:30/15:20/16:40，不使用行程本身耗时；还截断原始多日路线为三段。
- 演示分类函数用任意地点生成模板标题、临时 ID，覆盖预算和标签；结果 ID 不一定能在详情/行程中找到。
- 演示抽取没有执行人数、分类、预算、天数约束。无偏好直接抽取还可能复用上次结果。
- 服务端 PC 入口允许 itinerary_workbook 绕过 published/70 分门槛；分类在部分路径仅参与评分。
- 首页不足四条时残留模板攻略；真实内容回来后没有同步封面，造成图片与路线不一致。
- 详情中的“本周六适合出发”、交通/补给已纳入考量等文字没有证据。当前没有出行日期字段，不能把当前天气当成未来出行日预报。

## 修正后的规则

- 六分类按明确标签筛选，不从“坊/巷/公园”等词推断美食，不通过改写标题制造候选。
- 无符合分类、人数、预算和天数的候选即失败；本地失败不扣次数。多日不再用几个下午活动拼成完整旅行。
- 结果使用稳定 ID，可继续查详情、加入行程和重载。API 和本地预览仍是不同存储；不会把本地数据冒充云端存储。
- 详情使用结构化分段时间累计，计入步行缓冲；无结构化时间的数据只展示原有步骤，不编造时刻。
- 准备清单按活动展示手机、充电宝、线缆、证件、预约凭证、鞋服等。相机标为可选。
- 地图总览使用文字下划线。手机时间、耗时、圆点同一行对齐，去掉卡片负边距；导航栏不再遮挡滚动时间。
