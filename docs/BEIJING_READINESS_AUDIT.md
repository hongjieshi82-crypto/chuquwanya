# 北京试点与核心流程验收

本轮保留 Expo / Express / MySQL 架构，完成已授权的核心流程修复。成本控制及商业化暂不调整。

## 已验证

- 真实本地 MySQL 已恢复，037、038 迁移已执行。
- `scripts/smokeTripLifecycle.ts` 使用独立 QA 访客，通过真实 HTTP 接口验证连续四次生成、结果恢复、收藏、安排、开始、暂停、进度读取、恢复、反馈排除、改期。

- 行程进度有服务端持久化接口，页面读取完成后才开放步骤操作。
- 快速抽取弹窗关闭时清空出发模式与日期。

## 北京内容

试点场景：今晚短途、周末双人约会、低预算半日。

已有参考候选包括亮马河、什刹海、北海、地坛、砖塔胡同等；本轮补入簋街夜宵、亮马河夜间双人约会。参考时长与预算为编辑估算，不是实时报价或交通测算。

夜间属性依据：[北京市夜京城指南](https://www.beijing.gov.cn/ywdt/gzdt/202408/t20240827_3783414.html)。该来源支持区域的夜间活动属性，不支持每家商户当天营业、实时通行及价格。

封面只复用相同地点的图片。其他城市夜游无对应照片时使用明确标注的原创主题示意，不能当作地点实拍。

北京参考目录已导入本地数据库 review 区：`node --import tsx scripts/importPracticalItineraries.ts --city=1 --apply`。重复导入不覆盖已有数据。

## 人工浏览器验收清单

浏览器工具因当前 URL 访问限制已停止，本清单需要人工验收；接口验证不能替代视觉与多设备交互验收。

1. 登录同一个测试账号，在北京选择当天、预算200元以内、休闲躺平，生成并查看路线、地图和开放提示。
2. 选择双人约会，确认不会改变人数约束；日期选未来可用日。
3. 晚间选择城市散步或美食吃喝、现在出发，确认时刻与当时营业窗口相符；恶劣天气可能正确无结果。
4. 连续换四次，确认没有次数提示；刷新后继续，确认保留同一轮去重。
5. 收藏后在行程中安排，开始、暂停，在另一设备登录同一账号重新进入行程，检查进度恢复。
6. 断网操作后检查同步错误和重试入口；恢复网络后同步，并核对服务端状态。
7. 提交不适合我的反馈，再生成时应排除该地点。
